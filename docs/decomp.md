# The decompilation pipeline — from lifted C to real, structured C++

How a function travels from machine-generated lift to readable, verified,
structured code. The registry (`data/function_states.json`, generated by
`Scripts/decomp_dashboard.py`) tracks every function's stage; `MATCHING.md`
renders the counts. Committed on milestones, like `docs/bringup_log.md`.

## The two tracks

| Track | What it is |
|---|---|
| **Executable** (`Source/lifted/` + win32hle) | pcrecomp's mechanical lift of all 19,140 functions — 1.39M lines of state-machine C that boots and runs the game. Ground truth, never hand-cleaned. |
| **Readable** (`Source/<module>/`) | Hand-written C/C++ with real signatures and types, one function per file, differentially verified against the original bytes. |

A readable function replaces nothing until it has proven itself: the lifted
body stays the oracle the whole way (docs/matching_plan.md).

## Pipeline stages (what the registry tracks)

```
lifted  ->  autoported  ->  verified  ->  promoted  ->  active
   (all)     (Scripts/       (difftest     (readable C in     (override wired
              auto_port.py)   green)        a module dir)      into the boot)
```

- **lifted** — every cataloged function (19,140). Machine C only.
- **autoported** — mechanically ported leaf function (`Source/autopilot/`),
  compiled and fuzzed by the autoport pipeline.
- **verified** — passed the differential test against the original x86 bytes
  (unicorn: same inputs -> same eax, same memory writes; 40+ fuzzed cases).
- **promoted** — a hand-written, *readable* reconstruction exists in a module
  directory with real types and a real signature.
- **active** — wired into the running game through the override mechanism
  (`Source/host/overrides.c`); the boot behaves the same with it in.

## Module layout (docs/matching_plan.md's map)

`Source/<module>/` per engine subsystem — `app`, `win`, `gfx`, `data`,
`game`, `net`, `sound`, `crt`. A function is classified by, in order:
its scoped-assert/engine-string name's class prefix, its address band
(`crt` = 0x5F0000–0x610000, `thiscod` = legacy code section), the Win32
libraries its code touches, else `unclassified`. The classifier lives in
`Scripts/decomp_dashboard.py`; refine it as naming grows.

## Promoting a function (the loop)

1. **Choose** — boot-path first, then callers/size (the dashboard's
   "Promotion targets" table), then the 66 diverged manual targets.
2. **Understand** — read the lifted C (`Source/lifted/recomp_00XX.c`,
   search `sub_00XXXXXX`), the original disassembly
   (`Scripts/disasm.py`, capstone), and every caller/callee.
3. **Reconstruct** — write real C/C++ with the *original's* ABI (cdecl/
   stdcall/thiscall, real argument types) in `Source/<module>/<name>.cpp`.
   Name it after what it does, document the address, and record every
   semantic the original exhibits (flag widths, undefined behavior, float
   quirks — see `Source/engine/geom_compare.cpp` for the standard).
4. **Match** — byte-exact under VC6 is the bar now: `MATCH_FUNC(0xADDR)` +
   `Scripts/match.py` (docs/matching.md). Use the differential test below only for
   code VC6 can't match yet. It can pass wrong code, because random fields rarely
   reach the deep paths.

   Differential test against the original bytes:

   ```
   ./venv/bin/python Scripts/verify_one.py <va> <file.cpp> <symbol> \
       <cdecl|stdcall|thiscall> <n_stack_args> [--cases N] [--this-bytes N]
   ```

   It runs the original bytes and the mingw-compiled reconstruction under
   unicorn with identical fuzzed inputs (`this` object + stack args) and
   compares eax and every memory write. No green, no promotion.
   (`Scripts/diffharness.py` holds the two existing fixtures;
   `refs/pcrecomp/tools/lift/difftest.py` answers lift-side questions.)
5. **Register** — the dashboard picks the file up by filename
   (`sub_XXXXXX.cpp`) or header comment; rerun it, commit.
6. **Activate** (optional but the point) — add an override in
   `Source/host/overrides.c`:

   ```c
   void sub_00XXXXXX(void) {   /* runs inside the lifted model */
       /* read stdcall args: A32(i)/APTR(i)/ASTR(i) — g_esp -> [ret][arg0].. */
       RET(result, argc);      /* eax = result; pops ret + argc*4 */
   }
   ```

   The boot must behave identically (headless run + frame dumps); then the
   lifted body is retired in the registry, never deleted.

## Conventions

- One function per file, named for the function (`sub_00465270` until a real
  name is proven; rename in the registry, keep the address in a comment).
- Types go in the module directory (`Source/<module>/types.h`) as they are
  recovered from `this`-usage and vtables — the engine is C++.
- Coordinate with `refs/aoe2-decomp` (Conquerors 1.0c + AoK 2.0a) and
  `refs/swgb-recomp` for names and vocabulary; never duplicate.
- No copyrighted assets in the repo; the game tree stays outside.

## Dashboard

`data/function_states.json` + `MATCHING.md`. Sources: the disasm32 catalog,
the IDA-view function list, `verified_functions.json`, the symbol map,
engine strings, the reconstruction directories, and the override file.
