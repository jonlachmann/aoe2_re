## Skeleton tree
`Source/skeleton/` holds declarations only, generated from this map and
not compiled by `Scripts/match.py` or the boot: one header per vtable class,
one per inferred non-virtual class, plus `Source/skeleton/free/free_<region>.h`
for functions with no class evidence. Signatures are placeholders, not ABI
claims. Regenerate with `Scripts/class_map.py`; do not hand-edit.

## Limitations
- 154 vtables have no proven class name and are
  labelled by address; the slot names inside are also mostly unknown.
- Vtable boundaries are inferred from consecutive constructor writes; a class
  with no recovered constructor can be merged into a neighbour. Slot order is
  exact; the boundary is the inference.
- 281 of the non-virtual classes are `cluster` candidates: a component of
  functions connected only by `ecx = this` edges, with no global/member root.
  They are a work grouping, not a proven class name.
- A callee with call sites supplying *different* object identities is left
  unclassed: that is either an inherited method or a generic helper, and needs
  more evidence. Only agreeing call sites were assigned.
- A shared vtable slot (present in several derived vtables) is treated as a
  base/inherited method for inference; it appears in each derived skeleton header
  as a slot but does not pin a derived class.
- `module` is a hint from known names/imports and falls back to the address
  region. It is not a claim about the original source file.
